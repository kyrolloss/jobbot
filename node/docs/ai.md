# AI actions

Environment names: `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_MIN_GAP_MS` (5000), `GEMINI_TIMEOUT_MS` (60000), `GEMINI_MAX_OUTPUT_TOKENS` (8192; 0 disables cap), `GEMINI_PRICE_PER_MTOK_INPUT`, `GEMINI_PRICE_PER_MTOK_OUTPUT`, and `PROFILE_PATH` (`../profile.md`). Gemini credentials are optional at startup; absent key/model returns `GEMINI_NOT_CONFIGURED` on generation routes.

Node ports the Python evaluator, proposal writer, estimate parser, and estimate pricing formulas. Prompts retain the source Arabic/English instructions. Gemini calls share a serialized client with a five-second default gap, three quota attempts, a 60-second default timeout, and 8192 output tokens. A finite output cap also applies to thinking models; their internal reasoning tokens count against the cap, so a complex response may truncate sooner. Set `GEMINI_MAX_OUTPUT_TOKENS=0` to omit the cap.

Generation endpoints return stored results for free; only missing/regenerated results call Gemini through the SaaS guard. A per-user/job/feature in-flight lock returns `ALREADY_RUNNING`. The credit ledger prevents duplicate charging for an idempotency key; after a failed/refunded attempt it creates a retry-specific ledger key so the same client key can retry. Profile data comes from `user_profiles.profile_md`, with the owner file fallback resolved at call time. An approved transition is attempted only from `sent`; for any other status the proposal is still saved while status stays unchanged. `applied` remains controlled by its existing action.

Radar emits `radar_alert` immediately, then queues one owner proposal after releasing the scan lock. Proposal failures are swallowed and logged without credentials; success stores the proposal, approves a sent job, and emits `proposal_ready`. SaaS-user radar proposals are not enabled yet. The Node estimate stores the Python estimate object and computes pricing from shared Node `jobs` rows; the endpoint also returns computed pricing alongside the estimate under `result.pricing`.

Assumptions and known limits: source stats refresh is best effort and uses existing source `fetchStats` methods; estimate market medians use saved shared rows only. Gemini prices remain unset unless supplied through env. Usage schema requires numeric `cost_usd`, so the DB records zero when no token prices are configured, while the endpoint reports `cost_usd: null`. The Python code had no `maxOutputTokens` cap; Node uses the configured generous cap for bounded responses.
